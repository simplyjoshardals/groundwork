- 2026-11-02: Task 1.5 (extraction module) closed. `lib/pdf/` exports `extractPages(buffer: Uint8Array, mimeType: string): Promise<PageInput[]>`, returning the `{ page, text }` shape from `lib/chunking`. PDFs use `unpdf` 1.9.1 as validated in Task 0.6 (spike code was reimplemented, not imported; `spikes/` is untouched): one entry per physical page, 1-based, blank pages kept, text not normalized (the chunker normalizes). `text/plain` and `text/markdown` are decoded as strict UTF-8 and passed to the existing `paginateText()`; Markdown is not parsed or stripped. Checks run in this order: argument types (wrong types throw `TypeError`), size over 5 MiB, zero bytes, MIME type (lowercased, parameters ignored; only `application/pdf`, `text/plain` and `text/markdown`), then content: `%PDF-` within the first 1024 bytes for PDFs (the spike's rule), and for text no NUL bytes (this also rejects UTF-16) and valid UTF-8 (a BOM is stripped; invalid bytes are rejected, never replaced). The MIME type is a routing hint only. Limits (`lib/pdf/limits.ts`, kept local until `lib/config.ts` exists): 30 pages and 5 MiB. The 30-page limit also applies to virtual text pages, because `documents.page_count` is capped at 30 for every type; it is checked before any PDF text is extracted. Errors: every file problem is an `ExtractionError` subclass whose `code` equals a `documents.error_reason` value (`ScannedPdfError` `scanned_pdf`, `TooManyPagesError` `too_many_pages`, `FileTooLargeError` `file_too_large`, `UnsupportedMimeTypeError` and `InvalidFileSignatureError` `unsupported_type`, `CorruptPdfError` `corrupt_file`, `EncryptedPdfError` `encrypted_file`, `EmptyDocumentError` `empty_document`, `UnexpectedExtractionError` `internal_error`). Messages are fixed strings and no `cause` is kept, so raw library output never reaches callers. Only `PasswordException` (encrypted) and `InvalidPDFException`, `MissingPDFException` and `FormatError` (corrupt) get specific codes; any other library error becomes `internal_error`. Whitespace-only text is `empty_document`; a PDF with no text is treated as scanned. Owner-password-only PDFs are accepted (the product decision Task 0.6 left open); only PDFs that need a password are rejected. Cleanup: the document proxy in unpdf 1.9.1 has no `destroy()`, so `loadingTask.destroy()` runs in a `finally` and a cleanup failure is swallowed, never replacing the result or the original error. Scanned detection is a provisional heuristic, not OCR detection: a PDF whose average non-whitespace characters per page is below 25 (`MIN_AVG_CHARS_PER_PAGE`) throws `ScannedPdfError`. The 25 comes only from synthetic fixtures (two generated scans averaged 0 and 5; the sparsest real-text fixture 59) and was never checked on a real scan. Known limits: a real scan with a stamp, Bates number or OCR layer averaging 25 or more passes and yields junk chunks; an image-heavy text PDF such as slides can be falsely rejected; it uses the average, so a half-scanned document can pass; garbled text from unmapped fonts counts as characters and passes. Re-check on real documents before relying on it. Tests: `tests/unit/pdf-extract.test.ts` (45 tests) uses fixtures copied from `spikes/pdf/fixtures/` into `tests/fixtures/pdf/` (so they survive the Task 6.9 removal of `/spikes`) and `tests/unit/helpers/pdf-builder.ts` to build the 31-page and blank-page PDFs in memory; the cleanup tests wrap the real PDF.js objects with spies. Verified: lint, typecheck and unit tests pass locally, as reported by the project owner. Claude's own sandbox checks (fixtures regenerated with the spike's `make_fixtures.py`, dependencies installed with npm): the new tests fail when cleanup, the threshold or the page limit are deliberately broken, and the module ran with the real `server-only` marker through `tsx --conditions=react-server`. Not verified: `next build` (nothing in `app/` imports `lib/pdf` yet), behaviour on real scanned or real-world PDFs, and a GitHub Actions run on this change. Not built: OCR, size or page limits for anything but the values above, and any ingestion, storage or API use (Task 1.6 and Slice 4).
