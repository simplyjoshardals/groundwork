# Decisions log

One dated line per decision that changes the design. Newest at the bottom.

- 2026-10-29: Keep the Next.js `app/` directory at the repo root (no `src/`). Other folders (`components/`, `features/`, `lib/`, `types/`) also live at the root; the `@/*` alias maps to `./*`.
- 2026-10-29: Next 16 replaces `middleware.ts` with `proxy.ts`. Session refresh (task 1.7) goes in a root-level `proxy.ts`.
- 2026-10-29: Removed `cacheComponents` and `partialPrefetching` from `next.config.ts`; neither was intentional and Cache Components changes how cookies and Supabase calls behave.
- 2026-10-29: Local development points at the local Supabase stack via `.env.local`; hosted project values live only in Vercel env vars.
- 2026-10-29: Bumped `@types/node` to `^22` (matches the Node 22 runtime; Vitest 5 requires `^22 || >=24`, and npm refuses to install with `^20`).
- 2026-10-31: Task 0.5 embedding decision: `gemini-embedding-2` at 768 dimensions (`vector(768)` stays), with no additional L2 normalization (768-dimension vectors measured unit length; Google documents automatic normalization for reduced dimensions). The adapter applies the document prefix `title: none | text: {text}` at ingest and the query prefix `task: search result | query: {text}` at search time (no `taskType`), and the exact model id is stored per chunk in `chunks.embedding_model`. Evidence: `docs/spikes/provider.md` section 5.6 (USER-verified, not independently file-inspected). Not decided here: quota accounting (and the quota behind the unpaced-run 429s) and real-PDF ingest time.
- 2026-10-31: Scope of provider use (Task 0.5): free-tier terms for Gemini and Groq were reviewed; free-tier use is acceptable for this personal portfolio project during development with synthetic or non-sensitive documents. If it becomes a real product, reassess paid-tier privacy and data-handling requirements. LLM roles remain provisional: Gemini primary, Groq fallback.
- 2026-10-31: Task 0.4 (CI) closed. GitHub Actions (`.github/workflows/ci.yml`) runs install, lint, typecheck, unit tests and build on Node 22, with the version pinned via `actions/setup-node` in the workflow. Verified: a normal run passed all steps; a deliberately broken assertion in `tests/unit/spikes-provider.test.ts` failed the Unit tests step (then restored, local tests passing); the latest run on `test/ci-red-check` is green. Not tested here: pull-request-triggered runs, Playwright or the Supabase stack in CI.
- 2026-11-01: Task 0.6 (PDF extraction) closed. Library: `unpdf` 1.9.1 (bundles pdf.js 6.4.299), pinned below 2.x because 2.x declares Node 24 or newer while CI and local use Node 22. Verified on Vercel (function on Node v26.13.0, `iad1`) with 12 synthetic fixtures: correct per-page text on single-column, table, 30-page and owner-password-only PDFs; both scanned files flagged and no text file flagged with a threshold of 25 average non-whitespace characters per page (scans 0 and 5, sparsest text 59); user-password, corrupt and non-PDF inputs return controlled errors (`encrypted`, `corrupt`, `not_pdf`) and the instance kept serving. Measured: 30-page warm extraction 98.7 to 182.9 ms (3 runs); one cold sample 316.3 ms server-side on a 10-page file. Known limit: line-interleaved two-column text is not recoverable (0 of 14 fragments on those pages). Evidence: `docs/spikes/pdf.md`. Not decided: behaviour on real PDFs, the threshold on real scans, owner-password-only PDFs, a fix for interleaved columns, and Node 22 (CI) versus 26 (Vercel).
