- 2026-11-02: Task 1.4 (chunker) closed; recorded together with Task 1.5, so the date is when it was written down. `lib/chunking/` exports `normalizePageText`, `PIPELINE_VERSION`, `chunkPages(pages, options)` and `paginateText(text, options)`, and the `PageInput` (`{ page, text }`), `Chunk` and option types. Normalization lives in one place (`normalize.ts`) and `PIPELINE_VERSION = 1` matches the `documents.pipeline_version` default; changing any normalization rule changes the stored offsets, so the version must be bumped and old documents re-ingested. `normalizePageText` converts CR and CRLF to LF, tabs and NBSP to spaces, collapses space runs and trailing spaces, collapses 3 or more newlines to 2, trims the page, applies NFKC, removes soft hyphens, zero-width and bidi marks, the BOM and control characters (including NUL), keeps ZWJ, ZWNJ and variation selectors, replaces unpaired surrogates with U+FFFD, and is idempotent. `chunkPages` normalizes each page, then returns `Chunk { chunkIndex, pageNumber, charStart, charEnd, content }` where `content === normalizePageText(page.text).slice(charStart, charEnd)` (offsets are UTF-16 code units into the normalized page text, never the raw text). Chunks never cross a page and nothing overlaps across pages; pages keep input order; empty or whitespace-only pages are skipped and `chunkIndex` stays contiguous. Paragraphs are grouped greedily up to `maxChars`; an oversized paragraph falls back to a sentence, then a line, then whitespace boundary, then a hard cut that never splits a surrogate pair. Overlap snaps to a paragraph, sentence or word start and is usually a little smaller than requested, so read it from the offsets; a short final piece is merged when it fits and is never dropped. Defaults are `maxChars` 1200 and `overlapChars` 150 (provisional starting values, not empirically validated; the Slice 2 eval is where they get tuned), with a hard ceiling of 4000 for `chunks.content`. Sizes are in characters, not tokens. Invalid options, duplicate or invalid page numbers throw `RangeError`, and non-string page text throws `TypeError`. `paginateText` cuts `.txt` and `.md` text into virtual pages of about 4000 characters (numbered from 1, normalized first, ending at paragraph boundaries where possible, with no text lost or duplicated); Markdown is not parsed. The 30-page limit is deliberately not enforced in the chunker: extraction (Task 1.5) and ingestion own it. The module has no `server-only` marker on purpose, because the citation viewer needs the same normalization on the client to match chunk text against a rendered PDF text layer. Tests: `tests/unit/chunking-chunk-pages.test.ts`, `chunking-normalize.test.ts` and `chunking-paginate.test.ts` (82 test blocks) cover every Task 1.4 acceptance item plus overlap snapping, Unicode and CJK handling, validation and a generated-input invariants test. Verified: marked done by the project owner; in Claude's sandbox (dependencies installed with npm, fixtures regenerated) the full unit suite passed except `sample-docs.test.ts`, whose seed PDF was missing from the repository snapshot, and lint and typecheck passed for the whole repository. Not tested: chunk counts and chunk quality on the real sample documents (known only once Task 1.6 ingests them, which closes the open note in the 2026-11-01 Task 0.9 entry), retrieval quality, and whether 1200 and 150 are good settings.

Checks run in this order: argument types (wrong types throw `TypeError`), size over 5 MiB, zero bytes, MIME type (lowercased, parameters ignored; only `application/pdf`, `text/plain` and `text/markdown`), then content: `%PDF-` within the first 1024 bytes for PDFs (the spike's rule), and for text no NUL bytes (this also rejects UTF-16) and valid UTF-8 (a BOM is stripped; invalid bytes are rejected, never replaced). The MIME type is a routing hint only. Limits (`lib/pdf/limits.ts`, kept local until `lib/config.ts` exists): 30 pages and 5 MiB. The 30-page limit also applies to virtual text pages, because `documents.page_count` is capped at 30 for every type; it is checked before any PDF text is extracted. Errors: every file problem is an `ExtractionError` subclass whose `code` equals a `documents.error_reason` value (`ScannedPdfError` `scanned_pdf`, `TooManyPagesError` `too_many_pages`, `FileTooLargeError` `file_too_large`, `UnsupportedMimeTypeError` and `InvalidFileSignatureError` `unsupported_type`, `CorruptPdfError` `corrupt_file`, `EncryptedPdfError` `encrypted_file`, `EmptyDocumentError` `empty_document`, `UnexpectedExtractionError` `internal_error`). Messages are fixed strings and no `cause` is kept, so raw library output never reaches callers. Only `PasswordException` (encrypted) and `InvalidPDFException`, `MissingPDFException` and `FormatError` (corrupt) get specific codes; any other library error becomes `internal_error`. Whitespace-only text is `empty_document`; a PDF with no text is treated as scanned. Owner-password-only PDFs are accepted (the product decision Task 0.6 left open); only PDFs that need a password are rejected. Known limits: a real scan with a stamp, Bates number or OCR layer averaging 25 or more passes and yields junk chunks; an image-heavy text PDF such as slides can be falsely rejected; it uses the average, so a half-scanned document can pass; garbled text from unmapped fonts counts as characters and passes. - 2026-11-03: Task 1.8 (stream event contract and client parser) closed.
  verification. `types/ask-stream.ts` (types only) defines `AskStreamEvent`, `StreamSource` and `StreamErrorCode`; `lib/ask-stream/` holds `events.ts` (`encodeStreamEvent`, `parseStreamEvent`, `isTerminalStreamEvent`), `parse.ts` (`readAskStream`), `errors.ts` and `index.ts`. None of it imports `server-only`, because the server encodes and the browser parses. Task 1.9 needs only `encodeStreamEvent`. Wire format: each event is one SSE frame, `data: {"type": "...", ...}\n\n`, with the event type inside the JSON and no `event:` field. A `: comment` frame is allowed (for example an opening flush) and is skipped. Events: `sources` (`sources: { marker, documentId, documentTitle, page, snippet }[]`), `token` (`text`), `done` (`citations: number[]`, `invalidCitations: number[]`), `not_found` (optional `closest?: StreamSource[]`, omitted rather than null when absent), `limit` (`scope: "user" | "global"`) and `error` (`code: StreamErrorCode`, safe `message`). `marker` and `page` are positive integers; the arrays in `done` hold integers (an invalid marker such as 0 or 9 belongs in `invalidCitations`). Slice 3 may add `charStart` and `charEnd` to `StreamSource` additively: the parser ignores unknown fields, and rebuilds each source from its known fields only. `StreamErrorCode` is `search_unavailable`, `llm_unavailable`, `interrupted` or `internal_error`. The plan fixed only that `error` has a code and a safe message, so these four are a provisional choice taken from the ARCHITECTURE failure-mode table. The parser rejects an unknown code as a protocol error (client and server deploy together), so a new code means editing the type and the `ERROR_CODES` table, which the compiler checks for completeness; the client chooses the user-facing text and `message` is only a fallback. Terminal events: `done`, `not_found`, `limit` and `error` each end a complete stream. `readAskStream(body)` yields events as bytes arrive, then stops and cancels the reader right after the first terminal event; later bytes are never parsed, even if malformed. Failures: a stream that closes without a terminal event throws `StreamIncompleteError`; a final frame that never received its blank line is discarded (as the SSE specification says) and so also counts as incomplete. Invalid JSON, a payload that is not an object with a string `type`, or a known event type with an invalid shape throws `StreamProtocolError` (the message names the event and field and never echoes the payload). A failed read throws `StreamInterruptedError` with the original error as `cause`; an `AbortError` is rethrown unchanged. All three extend `AskStreamError`. Unknown event types: `parseStreamEvent` returns `null` and the stream reader skips them, so an old client survives a new server event type. A stream consisting only of unknown events is still incomplete. Framing handled: events split across chunks, several events in one chunk, CRLF (including a CR and LF in different chunks), multi-byte characters split across chunks (`TextDecoder` with `stream: true`), comment lines and frames, extra blank lines, non-data fields (`event:`, `id:`, `retry:`, ignored) and multiple `data:` lines in one frame (joined with a newline). A lone CR as a line ending is not supported. The errors live in `errors.ts`, not `parse.ts`, to avoid a circular import with `events.ts`. Tests: `tests/unit/ask-stream-events.test.ts` and `tests/unit/ask-stream-parse.test.ts` cover the four BUILD_PLAN acceptance cases plus the edge cases above and a check that no module in the folder imports `server-only`. Verified locally (as reported by the project owner): the full Vitest suite passes, including both new test files;yarn lint and yarn typecheck are clean.
