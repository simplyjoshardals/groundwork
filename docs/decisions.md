The adapter applies the document prefix `title: none | text: {text}` at ingest and the query prefix `task: search result | query: {text}` at search time (no `taskType`), and the exact model id is stored per chunk in `chunks.embedding_model`. Evidence: `docs/spikes/provider.md` section 5.6 (USER-verified, not independently file-inspected). Not decided here: quota accounting (and the quota behind the unpaced-run 429s) and real-PDF ingest time.

If it becomes a real product, reassess paid-tier privacy and data-handling requirements. LLM roles remain provisional: Gemini primary, Groq fallback.

- 2026-11-01: Task 0.6 (PDF extraction) closed. Library: `unpdf` 1.9.1 (bundles pdf.js 6.4.299), pinned below 2.x because 2.x declares Node 24 or newer while CI and local use Node 22. Verified on Vercel (function on Node v26.13.0, `iad1`) with 12 synthetic fixtures: correct per-page text on single-column, table, 30-page and owner-password-only PDFs; both scanned files flagged and no text file flagged with a threshold of 25 average non-whitespace characters per page (scans 0 and 5, sparsest text 59); user-password, corrupt and non-PDF inputs return controlled errors (`encrypted`, `corrupt`, `not_pdf`) and the instance kept serving. - 2026-11-01: Task 1.3 (provider interfaces and Gemini adapters) closed. `lib/providers/` holds the `EmbeddingProvider` and `LlmProvider` interfaces and the Gemini adapters. Embeddings: `embed(texts, role)`; the adapter applies the 2026-10-31 embedding decision (`gemini-embedding-2`, 768 dimensions, document prefix `title: none | text: {text}`, query prefix `task: search result | query: {text}`, no `taskType`, no extra L2 normalization), so callers pass raw text and already-prefixed text is rejected; at most 100 texts per call, with no pacing or batching in the adapter (ingestion paces). LLM: `stream(messages)` yields only provider-level `text` and `finish` events; the Task 1.8 application contract is separate. Errors normalize to `RateLimitError`, `ProviderUnavailableError` and `BadRequestError`; 401, 403 and `API_KEY_INVALID` stay `BadRequestError` with `status`, `providerCode`, `providerReason` and `isAuthError` preserved; malformed provider output and mid-stream failures are `ProviderUnavailableError`; raw provider bodies are never kept. Gemini is the only adapter: no Groq adapter or failover was built (Groq stays a spike-tested alternative; failover is Task 5.5). The LLM model is not decided: `gemini-3.5-flash-lite` is the default and streamed successfully in the smoke test, but it remains provisional (see the 2026-10-31 scope entry) and is configurable through the `model` option or `GEMINI_LLM_MODEL`; the Slice 2 eval is where candidates get compared. Verified locally by the project owner (as reported): `yarn install`, lint, typecheck, unit tests and build pass; a temporary Client Component importing `@/lib/providers` failed the build through `server-only` (page deleted afterwards); `yarn provider:smoke` against real Gemini returned 768-dimension, all-finite document and query vectors and a streamed answer ending in a `stop` finish event. Not tested: HTTP 429 and 5xx from the real API (unit tests use mocked responses shaped from Google's documented error format; a real 429 body was never captured), whether an invalid key arrives as 400 `API_KEY_INVALID`, a GitHub Actions run on this change, and behaviour under real ingest load. Spike code was copied, not imported, and `spikes/` is untouched.
- 2026-11-02: Task 1.4 (chunker) closed. `lib/chunking/` holds the pure normalization, pagination and chunking code. `normalizePageText` is the only place text is normalized (drops invisible and control characters but keeps ZWJ/ZWNJ and variation selectors, then NFKC, then whitespace and newline cleanup); `PIPELINE_VERSION = 1` matches the `documents.pipeline_version` default and must be bumped if any normalization or chunking rule changes. Chunk offsets `charStart` (inclusive) and `charEnd` (exclusive) are UTF-16 code units (what JavaScript `slice()` uses) into the NORMALIZED text of the page, so `content === normalizePageText(page.text).slice(charStart, charEnd)`; chunks never cross a page and never split a surrogate pair. `.txt`/`.md` text is cut into virtual pages of about 4,000 characters by `paginateText` (`DEFAULT_VIRTUAL_PAGE_CHARS`), at paragraph boundaries where possible. Provisional chunk defaults: `maxChars = 1200` (hard ceiling 4000, matching the `chunks.content` check) and `overlapChars = 150` (a maximum; the real overlap snaps to a paragraph, sentence or word start). These are starting values, not empirically validated retrieval settings; Slice 2 (tasks 2.2 and 2.3) is where they get measured and may change, and any change to them should be recorded here. Task 1.6 must store `charStart` and `charEnd` directly as `chunks.char_start` and `char_end` and must not recalculate them with PostgreSQL `char_length()`, which counts code points rather than UTF-16 code units and would disagree for characters outside the Basic Multilingual Plane (such as emoji). Verified locally by the project owner (as reported; not run in Claude's sandbox): lint, typecheck, Prettier, the full test suite (259 tests across 11 files) and the production build all passed. Not tested: chunk counts and retrieval quality on the real sample documents (first visible in Task 1.6 and measured in Slice 2), and a GitHub Actions run on this change.
